# Estimo Roadmap

This file is the **single canonical source** for the plan and its progress. Architectural
rationale lives in [ARCHITECTURE.md](ARCHITECTURE.md) and [RESEARCH.md](RESEARCH.md); this
file answers "what, in which order, and is it done".

## Tracking rules

- Every item carries an ID (e.g. `S2-3`). PRs reference the item by its ID and tick the
  checkbox **in the same PR** (see [AGENTS.md](../AGENTS.md) §2.6).
- Sprint status: 🔵 Planned · 🟡 In progress · 🟢 Done · ⏸️ On hold.
  There is always at most one active sprint (🟡).
- Items are never silently deleted or altered; scope changes are justified in the PR description.
- The next sprint does not move to 🟡 until the current sprint's exit gate is met.

## Phase map

| Phase | Sprints | Goal | Version target |
|---|---|---|---|
| **F0 — Foundation** | S0 | Repo + data foundation: synthetic fixtures, ledger schema, seed set inventory | v0.1 ✅ (documentation) |
| **F1 — PoC** | S1–S4 | BRD → decomposition + questions + draft with analogy evidence; blinded evaluation on the golden set | v0.4 |
| **F2 — Dogfood Pilot** | S5–S8 | Code awareness + effort bands + review UI + calibration loop; use in the real workflow | v1.0 |
| **F3 — Productization** | S9–S10 | Connectors, multi-tenant, BYOC, Atlassian surface, MCP server | v1.x |

**Blinded evaluation gate (F1→F2):** AI-only / human-only / hybrid comparison on the
golden set; pass if the hybrid flow saves time over human-only without regressing on
calibration. Delta against the naive baseline is mandatory in every report
([PRINCIPLES](PRINCIPLES.md) #7).

## Continuous tracks (apply to every sprint)

- **E — Evals:** Every PR that changes estimation behavior carries a golden-set report;
  naive baseline mandatory (PRINCIPLES #7); judge ≠ generator; periodic human-labeled re-anchoring.
- **G — Security & licensing:** Real-data ban (SECURITY.md); dependency license audit
  (AGPL/SSPL/BUSL/ELv2 → ADR required); gateway version pinning.
- **D — Doc hygiene:** No plan/status documents are produced outside the canonical files;
  content going stale is fixed or deleted in the same PR (AGENTS.md §2.4).
